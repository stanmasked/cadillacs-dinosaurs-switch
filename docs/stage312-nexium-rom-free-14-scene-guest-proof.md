# Stage312 — actual NeXium guest proof for 14 invented CPS-1 scenes

Stage312 goes beyond successful host-native rendering (Stage309), safe fake
SD staging (Stage310), and early libnx SD mounting (Stage311). It compiles
a **separate opt-in** Nintendo Switch NRO and attempts to execute that NRO
inside the pinned NeXium Linux guest with exactly the two **artificial**
diagnostic files.

## Private emulator inputs

- ROM-free Stage308 `gfx.bin`, exactly 4,194,304 generated bytes
- Stage307 `sequence.bin`, exactly 875,160 generated bytes of 14
  deliberately invented 384x224 CPS-1 scenes, 2 FPS
- **No Capcom ROM**, firmware, keys, user data, private original graphics,
  captured gameplay, original MAME executable or INP/WLF replay

The workflow obtains the same SHA-256-pinned NeXium nightly as the
existing genuine guest training-room replay, then creates a *temporary*
`NEXIUM_DATA_ROOT/sdmc/switch/cadillacs-dinosaurs-switch/` with those
files. This is the exact guest `sdmc:/switch/...` mapping documented by
the upstream `nexium-common/src/paths.rs` and
`nexium-kernel/src/fs_host.rs` implementations.

## Real native guest witness

The exclusive compilation define
`DINO_SYNTHETIC_SCENE_GUEST_PROBE` is **disabled in the default NRO**.
When explicitly enabled and the local graphics carry the artificial
Stage308 marker, and when CPS1SEQ1 decodes exactly 14 scenes at 2 FPS:

1. The actual native Switch C scene compositor decodes the next scene.
2. It draws the frame at 3× scale into the libnx framebuffer.
3. The guest calculates one FNV64 over the native 384x224 scene RGBA,
   and a second FNV64 over sampled pixels in the outgoing framebuffer.
4. Only **after** `framebufferEnd()` the NRO writes a concise
   `FRAME_SUBMITTED` row to the isolated guest SD.
5. After recording all fourteen ordered indices, it exits the scene loop.
   A missing file, incorrect header, partial write, or failed emulation
   must not report success.

An independent verifier reads the **guest-created** CSV from the isolated
NeXium SD and computes all 14 expected scene FNV64 hashes with Python
using the known ROM-free artificial pattern and synthetic states. It
rejects absent, duplicated, out-of-order, malformed, unknown or pixel-
mismatching rows. Framebuffer samples must be nonzero and varied.

The workflow uploads only an aggregate JSON report, **not** the 4 MiB
graphics, frame images, the raw guest CSV, ROMs, emulator profile or
user paths. An artifact produced by a host fixture test is not treated
as runtime evidence; CI must actually launch the pinned NeXium binary.

## Reproduce

~~~sh
python3 -m unittest discover -s tests \
  -p 'test_nexium_synthetic_scene_guest_312.py' -v
~~~

For the real guest run, use
`.github/workflows/cps1-synthetic-scene-guest-312.yml`. It compiles an
actual NRO in devkitPro, verifies its NRO header and diagnostic strings,
pins NeXium's archive SHA-256, builds the fresh artificial SD fixture
outside the GitHub checkout and validates a genuine guest-written trace.

**Evidence boundary:** If that workflow passes, it proves that the
artificial scenes were decoded, rendered and submitted in real NeXium
guest execution, with the native scene pixels matching Python. It does
**not** prove those pixels reached a physical Nintendo Switch display,
the host-visible emulator window showed every frame, original game ROM
frame parity, historical WolfMAME replay or playable gameplay. Keep the
PR Draft and `main` unchanged.
